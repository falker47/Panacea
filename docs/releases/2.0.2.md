# Panacea 2.0.2 — UX and Italian localization (QA candidate)

This candidate follows stable [v2.0.1](https://github.com/falker47/Panacea/releases/tag/v2.0.1). It is **not a published release**.

- Larger original logo and proportionally larger sidebar branding with no title overflow.
- Check updates, release actions, developer credit and current version grouped in the bottom sidebar footer.
- No hidden secondary navigation: Cleanup and Installed apps, Repair tools and Drive optimization, Performance settings and Startup apps render together in two columns, with a compact layout on constrained windows.
- Installed setup language is saved in a protected sidecar file; Italian and English affect program controls, dialogs and status labels, not just Inno Setup's wizard. Source/portable versions follow Windows UI language unless explicitly overridden for QA.
- The overview uses viewport-aware vertical spacing, the three group headers are left-aligned, and paired panels reflow from available canvas width rather than a fixed 1000px host threshold.
- Performance & Startup shows its Startup apps heading only once, with a simpler Windows settings card; developer credits and the version share one footer row.
- Guided Maintenance has a prominent header, safe-start warning, progress/status hero, numerical progress, readable numbered cards with expandable details and a single responsive scroll/log surface. The original ten-step engine and mandatory verified restore point remain unchanged.
- The 26 October visual QA correction removes duplicate titles and nested Windows-settings boxes, adds icon-led commands, brings repair actions alongside their descriptions and fixes the vertically centered drive panel. The Overview has the same icon/title hierarchy as other sections and allocates extra window height to its cards.
- The Guided Maintenance layout now uses a compact sequence hero, a correctly sized warning and two columns of short step cards on ordinary desktop widths rather than requiring an excessively wide window.
- The existing guarded backend maintenance functions, safety confirmations, updater and rollback remain unchanged.

## QA requirements

Check both setup languages on a disposable Windows installation, including uninstall, then open all five sections at normal and 150% scaling. Confirm primary actions remain visible and no label/button clipping occurs; verify no maintenance runs at startup. For protected installations, verify the chosen language remains after an EXE-only update. Do not run destructive maintenance on a personal machine solely for visual QA.

## Distribution

Do not tag or release until human feedback and green Windows CI on this exact candidate HEAD.


## Visual and navigation follow-up — 26 October 2026

- Overview shows the installed Windows edition, elapsed time since last restart with a seven-day suggestion, and native charging state. The battery icon reflects reported charge rather than a decorative constant; Windows Update is vertically balanced and system-drive percentage avoids redundant wording.
- Quick cleanup is now a single action with progress feedback. Manual cleanup tools have compact inline actions. Duplicate diagnostic icons were removed, retaining purpose-specific graphics for restore point and battery report.
- Guided Maintenance uses an explicit, human-readable safety warning, discreet information controls and **3–4–3** sequence rows when there is enough room, with two- and one-column fallbacks. The verified restore-point gate, cancellation, incremental progress and logs are unchanged.
- An initial QA screenshot showed hidden pre-building could leave some CustomTkinter controls unpainted on their first display. Therefore views are now created on first actual selection, then kept alive; returning to them avoids repeated frame rebuilding and full-sidebar redraw. Read-only Windows visual evidence includes first and warm navigation timings; user-device performance acceptance remains pending.
