# Panacea 2.1.1 — Qt updater reliability

Panacea 2.1.1 is a maintenance update to the official **2.1.0 Qt Quick desktop**. It fixes error handling around the verified self-update helper without changing Panacea's Windows maintenance operations or replacing the trusted update backend.

## What changed

- **Helper started, staging cleanup fails:** a temporary download locked by Windows no longer causes Qt to discard the already-started helper job. The GUI continues monitoring the verified installation and its readiness/rollback result.
- **Helper cannot start:** the temporary verified download is cleaned up where possible so a later explicitly confirmed download can be retried instead of being rejected as already staged.
- **Temporary status/polling failure:** the GUI retains the running helper job and the update/maintenance exclusion, retries monitoring with bounded backoff, and avoids permitting overlapping installations.
- **Accurate failure messages:** an unavailable update status is not presented as proof that an old executable has been restored.

Four inert regression cases were added for these paths. No changes were made to the protected update engine's trust checks, ACLs, GitHub repository/asset allowlist, SHA-256 verification, readiness marker, backup retention, rollback, Inno Setup AppId or maintenance allowlists.

## Installation and updates

- **Protected installations of 2.1.0 or newer:** use the application's update check when it offers 2.1.1. Installation is **never silent**; confirm the verified update in the GUI. The installed edition checks official GitHub release metadata, verifies the download and uses the protected helper to replace the same `Panacea.exe`.
- **Installed 2.0.2:** the verified update flow is supported in principle, but each new stable release requires its own live upgrade acceptance; the official Setup is the manual alternative.
- **Installed 2.0.0/2.0.1 or legacy V1:** use `PanaceaSetup.exe` and its checksum for a manual upgrade. Do not use an unverified old in-app installer.
- **Portable executable in Downloads/Desktop:** automatic in-place replacement is deliberately disabled. Download `Panacea.exe` and `Panacea.exe.sha256`, verify SHA-256, close the portable app, then replace the file manually.

The installer retains the same protected Program Files application identity and does not modify unrelated portable copies. Permanent ZEROfilez links using `releases/latest/download/` continue to target whichever official stable release is published; they do not update previously installed software by themselves.

## Verification and limitations

The change is covered by RED/GREEN regression tests and Windows CI checks on disposable runners, including Qt/QML, native packaging, protected replacement and rollback, installer/update/uninstall and UI QA. **After publication**, an end-to-end live GitHub release update from the immediately previous installed version and the oldest supported updater is still required before declaring the full rollout accepted.

Neither CI nor SHA-256 certifies actual user-approved UAC, abrupt power loss, all Windows configurations or the affected GPD Win Mini; those limitations remain explicit. Executables are **not Authenticode-signed**. SHA-256 manifests check integrity against the published bytes but are not publisher signatures. Do not disable Windows security protections.
