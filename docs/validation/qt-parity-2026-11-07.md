# Qt Quick parity evidence — 7 November 2026

This change implements the eight V2 views inside the five approved Qt navigation groups. The source of truth is the current `panacea_ui.py`, not the historical seven-entry screenshots. It is a QA candidate, not permission to replace Panacea 2.0.2 or publish a release.

## Implemented behavior

- Dashboard matches the original uniform two-column summary and three-column metric grid, including compact logical viewports produced by 125%/150% scaling. It retains original icons, Windows Update state, battery/uptime, RAM capacities, disk thresholds, sixty-sample graphs and compact action cards. Interactive data comes from the original monitor and read-only backend. Italian content reuses the stable translation catalog; Qt-only text keeps its explicit fallback.
- Cleaning/Apps, Tools/Disk and Turbo/Startup reproduce shared panels and compact action rows, with fixed group headings and scrolling bodies. Logs are selectable plain text, retained per section, and expand when their operation starts. Unknown state never enables a maintenance switch.
- Disk selection is a keyboard-accessible popup rather than extra content in the panel. Unavailable drives can be inspected; optimization remains restricted to the available drive list and the backend validates the drive again.
- Resurrect keeps the original ten steps and order, expandable explanations, original safety warning and responsive 1/2/3/5-column grid. Actual success/failure is shown as each phase finishes and retained independently of other operations.
- Windows interactive confirmations use the Win32 message-box family used by Tk, default to No, and pass accepted decisions back through the existing one-use broker. Synthetic rendering and non-Windows platforms use the scrollable QML presentation. Tests reject stale decisions and repeated confirmation.
- The entire approved sidebar rectangle is unchanged from `53c4be03`: normalized UTF-8 SHA-256 `77dcfaa7f467b2d61722b13c46bb331a3e8f6b17d54155a0915c999a98d84b48`. No legacy production UI, backend module or artwork was modified.

## Reproduction

Use Python 3.12 with the repository development requirements and `qt_lab/requirements.txt`.

```powershell
python -m unittest discover -s qt_app/tests -p "test_*.py" -v
python -m ruff check .
$env:PANACEA_LANGUAGE = "english"
python -m pytest -q
python qt_app/parity_matrix.py --output build/qt-parity --mode all
```

The matrix captures eight views × three sizes × three simulated scales × two languages: **144 pairs**. It retains original legacy/Qt PNGs, side-by-side JPEGs, exact-dimension RGB differences and metadata. A separate **50-capture Qt** state matrix covers unknown, expanded, running, completed, partial, failed, cancelled, long-text and confirmation scenarios in both languages. It also runs **21 native legacy state cases** and produces **11 semantic-state A/B comparisons**. Those state comparisons use different synthetic inputs, so they are layout/feedback evidence, not assertions of identical data. These are inert fixtures; the capture services cannot start maintenance, network updates or Windows tools.

Qt metadata records the QML hashes, requested group, language, logical/image sizes, scale, fixture status and QML warnings. The report rejects stale source captures and warnings. RGB distance is diagnostic only; there is no automatic visual-approval threshold. The optional `--mode qt --reuse-matching` refreshes captures only when their QML and viewport metadata match; CI always captures from scratch.

The native display used locally was 96 DPI. Tk widget scaling and `QT_SCALE_FACTOR` are simulations, not a physical 125%/150% Windows display test. At 976×672/125% and 1366×768/150%, Qt can round the physical result by one pixel. At 976×672/150%, Qt's existing 760×480 logical minimum produces 1140×720, so those 16 pairs are explicitly unmatched. Images are never resized to conceal these differences. Hosted runners may also clamp legacy windows to their actual desktop size; that observed size is recorded and used for the Qt comparison.

## Regression and lifecycle evidence

The RED commit `6f029be0d9ea9dc8b6c3d65048a79f73ac5d9ed2` reproduced the misplaced summary and 1/2/2 guided-grid columns; [Windows RED run](https://github.com/falker47/Panacea/actions/runs/42362948462). Subsequent geometry tests check rendered QML rectangles, minimum-width overflow, fixed heading, popup panel height, long confirmation and compact Turbo placement. Popup opening first reproduced 203px instead of the closed panel's 157px, then passed without changing panel geometry.

The full scaling review also reproduced incorrect Dashboard wrapping at logical widths 760/781/911. The current V2 source keeps fixed uniform columns rather than changing their count. Qt now follows that structure, shares metric/action heights and uses the compact vertical allocation measured from the native V2 window. The rendered tests verify the columns and horizontal containment at those widths.

Native state capture exposed two defects in the inherited harness: it referenced the removed optional-tool `preview_label` instead of the shared Dashboard status, and fixture closure could reenter CTk's initial titlebar setup. The harness now uses the real shared label, initializes the native window before arming close callbacks and builds all deferred guided labels for state evidence. No legacy production implementation or fixture timeout was changed. A further RED/GREEN rendered-QML test ensures cancelled/failed sequences show remaining phases as **Not run**, matching the stable application.

The historical 45-second source-smoke failure has not been conclusively attributed to one cause. The deadline remains **45 seconds**. Startup now traces imports, application/bridge construction, QML load/configuration, capture, event-loop exit and engine disposal; faulthandler emits thread stacks if stuck. The workflow repeats native startup five times in separate processes and preserves traces even on failure. The QML engine is disposed while its bridge context is still alive.

Navigation profiles distinguish callback time, event/geometry processing and software frame capture for all five groups, first/warm. Legacy captures record corresponding diagnostic navigation timings. These are not equivalent compositor-latency benchmarks and do not substantiate a general claim that Qt is faster.

An initial full local suite under simultaneous capture load recorded a 30-second legacy child-process timeout (683 other tests passed). Keep that observation in the audit trail; the final full-suite run must be inspected separately, without changing the deadline. Local English tests use `PANACEA_LANGUAGE=english` because several inherited assertions assume English on this Italian host.
